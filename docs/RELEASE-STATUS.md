# Pre-Release Status

## What this repository is

**API Pre-Release Preview** is a documentation and demonstration package for the ONI custom simulation platform. It intentionally contains **no implementation source code**.

The purpose is to let modders and technically interested users understand the API, its design, its demonstrated capabilities, and the intended integration model before the implementation repositories are released.

## Expected source release

The related repositories and their currently private implementation source are **targeted for public release on Sunday, September 13, 2026**.

This date is a release target, not a guarantee. Final publication is dependent on completing release preparation, validation, documentation, and repository cleanup.

The preview should therefore be read as a **pre-release SDK reference**. API details may still change before public source release, although the goal is to make the documented modder-facing contract as stable and explicit as possible.

## What is included now

This preview contains:

- SDK/API documentation;
- architecture documentation;
- practical modder examples;
- showcase-rig documentation;
- AirLoop, PhaseLoop, and PipeStress demonstration videos;
- SimViz demonstration video;
- native extension/ABI documentation;
- compatibility and dependency guidance;
- known limitations and deliberate stubs;
- source-audit notes explaining how the reference was produced.

## What is intentionally not included

No private implementation repository is copied into this preview. In particular, the preview does not distribute the implementation source of:

- `ONI-Sim`;
- `ONI-Sim-Custom`;
- `oni-framework`;
- `oni-flagship`;
- `oni-simviz`;
- or other private development/reference repositories.

The preview documentation describes these systems without attaching their implementation source.

## Documentation status

The reference is being built by reading the actual source declarations and implementations, then tracing important APIs through their native and managed layers. It is **not** generated by treating filenames as an API inventory.

Each API is intended to be classified as one of:

- **Modder-facing** — intended as a supported integration surface;
- **Developer/diagnostic** — useful for tooling, tests, rigs, or diagnostics;
- **Internal plumbing** — implementation detail that mods should not call directly;
- **Experimental/stub** — exposed deliberately but not yet a complete gameplay system.

Where an API has meaningful behavior, the reference also documents units, timing, allocation behavior, compatibility behavior, native dependencies, and small usage examples.

## Source-release relationship

When the implementation repositories become public, this preview should remain useful as the high-level SDK entry point and reference manual. The source repositories will provide the implementation; this repository provides the modder-oriented explanation of how to consume it.
